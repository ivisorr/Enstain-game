## Фактическое состояние
- Движок: постоянный каталог ID 3 × 3, elementPositionById, случайный answer, answerPositionById, visibleElements.
- Публичные методы: startGame(), endGame(), getElements(), getVisibleElements(), getClues(). Геттеры возвращают независимые копии (строки массивов / объекты подсказок).
- startGame создаёт ответ, словарь его позиций, кандидатов и вызывает selectClues. После старта visibleElements пока [], после endGame — полное поле.
- clueCandidates — объект с пятью массивами given/sameColumn/leftOf/near/between. Генерация реализована ТОЛЬКО для given: по одному кандидату на каждый ID, колонка из ответа.
- cluesSelected — один массив. selectClues пока временно очищает его и копирует ВСЕХ кандидатов, не удаляя их из пула. Настоящий выбор, веса, лимит открытий и логический решатель не реализованы.
- checkClue удалена пользователем из движка; её адаптированный вариант находится только в tests/engine.test.mjs и получает позиции открытого поля параметром.
- В тестах fillPositionById(sourceMatrix) создаёт и возвращает новый словарь, без доступа к внутренним структурам движка.
- 6 тестов проходят через node --test: размеры, состав строк, независимость двух геттеров, сброс и истинность выданных подсказок.
- Последний тест фактически проверяет только given: остальные типы ещё не генерируются. Пустой или неполный список он пока не обнаруживает.

## Продолжение
Первым делом: [HANDOFF.md](HANDOFF.md). Добавить проверки полноты и отсутствия дублей given: каждому ID каталога соответствует ровно один кандидат. Далее по согласованию — другие типы, сброс коллекций и защита копии getClues. Новые задачи в конце прошлой сессии не реализовывались.

## Соглашения
- Каталог и строки постоянны, меняются колонки. Римские ID roman-I/II/III сохранять с заглавными буквами.
- Координаты rowIndex/colIndex; поле given теперь тоже colIndex (прежнее columnIndex заменено).
- Слой 3 хранит скрытый ответ и игровую логику; слой 2 отображает подготовленные данные и сопоставляет ID изображениям. Общий getState обсуждался, но реализованы отдельные геттеры.
- Кандидаты строим по позициям ответа, перебирая каталог. Для near исключаем обратную пару по порядку каталога. Для between каждый центр и пара из соседних колонок рассматриваются один раз.
- Стороны near/between случайно меняет местами ДВИЖОК после исключения дублей; middle не меняется. Это согласовано, но не реализовано.
- Финальное перемешивание не обязательно при будущем случайном выборе кандидатов и сохранении порядка выбора. Временное копирование всех кандидатов этого условия не обеспечивает.
- Для between пользователь исключил все три элемента одной строки; два из одной строки допускаются. Остальные настройки уточнять.
- Скрытие использованных подсказок пользователем — отложенная задача; вероятно состояние слоя 2.

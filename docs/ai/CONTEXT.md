Frontend-головоломка 6 × 6 с учётом будущего backend. Учебные цели: программирование, работа с AI, Git с двух компьютеров и CI/CD. Работа только в Enstain-game; соседние справочные папки не трогать и читать только по прямой просьбе.

Один пользователь работает поочерёдно дома и на работе, Windows, VS Code + Codex, публичный GitHub, main. Commit, push и получение изменений GitHub выполняет пользователь. AI разрешён просмотр локального Git без изменений. Версии инструментов и доступ к Codex дома ещё не подтверждены в документации.

Объяснения краткие, шаги небольшие, готовый код по запросу. Комментарии перед функциями и глобальными структурами обязательны. Элементы в прозе обозначаем [A], [1], [II]; индексы — без скобок. Note.txt в корне — личный буфер пользователя, автоматически не читать/не изменять.

## Согласовано

- Наборы и позиции строк постоянны; ответ — перестановка ID внутри каждой строки.
- Слой 3 — движок с ID и правилами. Слой 2 сопоставляет ID с alt/image; движок не зависит от них и DOM.
- elements — постоянная матрица ID; elementIndexById — ID → { rowIndex, colIndex } в этом каталоге.
- answer — матрица ответа; answerPositionById — ID → { rowIndex, columnIndex } в ответе. Словари производные.
- Атомарные подсказки: leftOf (left/right), near (side1/side2), between (side1/middle/side2), sameColumn (top/bottom), given (element/columnIndex).
- clueCandidates — объект с пятью массивами по типам; cluesSelected — один массив выбранных объектов. Кандидат переносится между ними, без selected. Слой 2 формирует три интерфейсных блока.
- Выбор типа по весу, затем кандидата; отдельный лимит открытых клеток. Значения настроек не выбраны.
- Генерация должна сохранять единственность и решение начальными логическими приёмами. Подробности — в профильных документах.

## Место остановки

В src/js/engine.js реализованы каталог ID 3 × 3, elementIndexById и fillElementIndexById() с вызовом. Пользователь изменил римские ID на roman-I, roman-II, roman-III — сохранять регистр.

Матрица answer и generateRandomAnswer() ещё не записаны в движок. Пользователь предложил распределять элементы каждой строки по случайным свободным колонкам. Его набросок разобран и исправлен в чате: answer — матрица, свободные колонки — индексы, а не ID, после выбора колонка удаляется через splice. Полный исправленный пример и пояснения сохранены в HANDOFF.md; этот пример не запускался. Продолжать с него по запросу пользователя, затем построить answerPositionById. Не повторять автоматически задание фиксированного ответа и не писать весь движок.

Перенос завершён и уже не ожидает подтверждения. Для следующей сессии прочитать [HANDOFF.md](HANDOFF.md), проверить локальные изменения и кратко напомнить: первая функция в файле есть, случайный генератор пока только в буфере.

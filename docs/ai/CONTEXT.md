## Реализовано
- src/js/engine.js: постоянный каталог ID 3 × 3, скрытый answer, словари elementPositionById/answerPositionById, visibleElements.
- Публичны startGame/endGame/getElements/getVisibleElements/getClues; геттеры возвращают независимые копии.
- clueCandidates — пять групп. Генерация готова для given, sameColumn, leftOf и near. between пока пуст; его алгоритм только описан в HANDOFF.
- given: {type, element, colIndex, id}; ID = given:elementId:colIndex.
- sameColumn: {type, top, bottom, id}; создаём только пару с нижней строкой, ID = sameColumn:верхнийID:нижнийID (порядок каталога).
- leftOf: {type, left, right, id}; перебираем все строки и все колонки правее текущей; ID = leftOf:leftID:rightID, порядок значим. Пока разрешены элементы одной строки, настройки ещё не реализованы.
- selectClues ВРЕМЕННО копирует всех кандидатов в cluesSelected; настоящего отбора, весов, лимитов и решателя нет. С добавлением near аналитически ожидаются 63 кандидата: 9 given + 9 sameColumn + 27 leftOf + 18 near. Полнота near отдельно не проверена.
- В tests/engine.test.mjs — 9 проходящих тестов. Три новых: защита копии getClues, соответствие ID содержимому, уникальность ID через Set. Истинность подсказок проверяет локальная checkClue по открытому ответу. Пользователь дополнил тест ID near нормализацией по строке и колонке каталога; все 9 тестов прошли после улучшений читаемости и диагностики.
- Словари тест строит сам через fillPositionById(getElements()/getVisibleElements()), внутренние словари движка не экспортируются.

## Проверки и продолжение
До добавления near по запросу пользователя выполнены отдельные логические разборы и независимые разовые проверки given/sameColumn/leftOf на 40 играх: полный точный состав кандидатов, ID, повторный старт, копии и неизменность каталога. Всё прошло. Эти разовые проверки НЕ сохранены в тестах и не запускаются CI.
Следующий шаг: см. [HANDOFF.md](HANDOFF.md). Пользователь выбрал сначала закончить генераторы: продолжить обсуждение between, затем случайные перестановки sameColumn/near/between без изменения ID. Алгоритм between описан, но код не реализован. Полнота near и between ещё не проверялась.

## Последние решения
- У sameColumn top/bottom теперь означают места в изображении подсказки, а не порядок строк. checkClue проверяет одинаковую колонку и разные строки. Тест ID независимо нормализует участников по каталогу. Случайный обмен ещё НЕ реализован.
- Для near и сторон between тоже согласован случайный порядок в движке, ID нормализуется независимо от порядка записи.
- Между двумя getClues одной игры набор и порядок стабильны: случайность при генерации, не в геттере.
- Полнота нужна пулу кандидатов, но НЕ будущему выбранному минимальному набору. Сохранённые тесты пока не проверяют полноту; временное копирование всех кандидатов позволяет разовую проверку.
- Скрытие использованных подсказок — отложенная задача. ID может пригодиться для этого.
- Каталог и строки постоянны; Roman ID roman-I/II/III с заглавными буквами. Координаты rowIndex/colIndex, у given тоже colIndex.
- between: все три элемента одной строки запрещены, два из одной допускаются; прочие настройки ещё уточнять.

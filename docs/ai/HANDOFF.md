## Предложенный алгоритм between — точка обсуждения
Внутри текущего обхода elements текущий elementId становится middle:
1. Его colIndex берём из answerPositionById.
2. Для крайней колонки пропустить только генерацию between, не остальные типы этого элемента. Нельзя continue вне цикла или return раньше других необходимых действий.
3. Все строки колонки colIndex - 1 дают первого бокового участника.
4. Для каждого первого участника все строки колонки colIndex + 1 дают второго.
5. Пропустить только тройку, где строки всех трёх одинаковые. Два из одной строки допускаются. Другие настройки ограничений пока не реализованы.
6. Стороны упорядочить по каталогу: сначала rowIndex, при равенстве colIndex. Центр не менять.
7. Предложенная запись: {type:"between", side1:firstSideId, middle:elementId, side2:secondSideId, id:"between:"+elementId+":"+firstSideId+":"+secondSideId}.
8. Добавить в clueCandidates.between.
Для данного центра каждая пара левой/правой колонок рассматривается один раз; дополнительно создавать обратное направление не нужно. В 3 × 3 ожидаются 24 кандидата: 3 центра × (9 пар - 1 случай одной строки). Это аналитический подсчёт, не проверка исполнения.
Добавить нормализацию сторон и центра в ветку теста ID. Истинность between уже описана в checkClue, но пока ни один between не генерируется.
Формат ID и реализация алгоритма — последняя предложенная схема, её ещё не реализовывали. Важные правила (центр между двумя соседями, запрет всех трёх из одной строки) ранее согласованы.

## Что добавлено в near
Блок в generateClueCandidates находится внутри row.forEach по elementId, рядом с given/sameColumn/leftOf, а не внутри их циклов.
const elementCatalogPosition = elementPositionById[elementId].
Перебираем neighborColIndex через for...of по [colIndex-1,colIndex+1], пропускаем границы, перебираем все строки answer.
Сосед назван neighborId, его позиция neighborCatalogPosition. Эти имена выбраны пользователем для единообразия.
Создаём пару, если строка соседа в каталоге больше либо строки равны и колонка соседа больше:
element.row < neighbor.row || (element.row === neighbor.row && element.col < neighbor.col).
Условие <= по строкам допускает обратные дубли одной строки; условие rowLess || colLess допускает оба порядка для разных строк. Эти вопросы подробно разобраны на примере [3] (0,2) и [A] (1,0).
near = {type:"near",side1:elementId,side2:neighborId,id:"near:"+elementId+":"+neighborId}.
Стороны пока фиксированы по каталогу, random НЕТ. В 3 × 3 без ограничений ожидаются 18 кандидатов near (подсчёт, не отдельный сохранённый тест).
Пользователь предпочёл комментарий с явным описанием сравнения индексов, он добавлен.
Независимая проверка полноты near предложена, но пользователь её НЕ запрашивал и она НЕ выполнена. Прежние независимые проверки 40 игр относятся к given/sameColumn/leftOf, не near.

После генерации всех типов добавить случайные перестановки, не меняя нормализованные ID:

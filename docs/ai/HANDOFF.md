Обновлено: 2026-11-25.

Тема: начальная структура логического решателя и продолжение состояния при добавлении подсказок.

## Где остановились
Пользователь согласился хранить возможные колонки отдельно от постоянного elements. По прямой просьбе AI добавил createPossibleColumnsById, пользователь переименовал её параметр в sourceElements и добавил локальный вызов в selectClues.
Последний вопрос: можно ли после добавления подсказки продолжать сокращать существующие варианты, а не решать заново? Ответ: да, при только добавляемых ограничениях прежние корректные исключения сохраняются. Нужно снова применять ВСЕ выбранные подсказки и правила строк до отсутствия изменений, поскольку новое условие активирует выводы из старых.
При удалении подсказок (этап сокращения) проще создавать исходные варианты заново: старые исключения могут больше не следовать из оставшегося набора.
Пользователь попросил зафиксировать и закончить. Подход обсуждён, но ещё НЕ реализован. Не превращать его в готовый интерфейс решателя без согласования.

## Фактический новый код
В src/js/engine.js:
createPossibleColumnsById(sourceElements) создаёт локальный объект possibleColumnsById, для каждого ID записывает отдельный row.map((_,colIndex)=>colIndex), возвращает объект. elements не меняется.
Параметр sourceElements выбран, чтобы не путать локальное имя с глобальным elements.
Пользователь в selectClues добавил:
let possibleColumnsById = createPossibleColumnsById(elements);
Это только создание состояния; оно пока не используется в canSolve или обработке условий. Полный тестовый набор после этого пользовательского изменения AI не запускал. canSolve(clues) остаётся заглушкой clues.length>9, отбор всё ещё до десяти подсказок без гарантии решения.
Пока переменная не переназначается, при следующем разборе можно обсудить const вместо let; на завершении код не меняли.

## Следующий учебный шаг
Согласовать небольшую первую часть решателя: применение given и правил строки к possibleColumnsById, а также результат при противоречии.
Варианты — отдельный словарь по ID, а не свойства элементов каталога:
- каталог ID постоянный;
- состояние решателя изменяется и принадлежит конкретному решению/проверке;
- массив каждого ID независимый, исключение колонки одного элемента не затрагивает массив другого.
Предложенные базовые приёмы: given оставляет указанную колонку, фиксированная колонка исключается у остальных ID той же строки; единственный возможный элемент колонки фиксируется. Потом отношения sameColumn/leftOf/near/between и повторение до неподвижной точки.
При добавлении подсказки — продолжить состояние; при удалении — пересчитать заново. Противоречие, полностью решено и остановка с вариантами должны различаться. Тайный answer решателю не доступен.
Код обработки given и настоящая логика canSolve НЕ написаны. Сначала согласование, показ в чате, потом отдельная просьба на изменение файлов.

## Терминальный просмотр — сохранять согласованный формат
Запуск из корня: node scripts/preview.mjs.
Подсказки — три блока одинаковой ширины (минимум 5 символов внутри скобок):
between: [side1][middle][side2];
near: [side1][ < > ][side2];
leftOf: [left][ >>> ][right];
sameColumn: [side1][ ↑ ][side2].
given выводится отдельно одним блоком, с номером строки/колонки от 1.
Ответ — матрица с теми же размерами ячеек, исходные открытия given выделяются КРУГЛЫМИ скобками, остальные клетки квадратными. Подписи: числа, заглавные буквы, римские числа, Д1… для domino; данные отображения находятся в скрипте, не движке.
Каждый запуск создаёт новую игру, потом раскрывает правильный ответ. Это инструмент ручного просмотра, не игровой UI. Отбор десяти пока не гарантирует решаемость.
Скрипт проверен обычным запуском. Отдельной разовой проверкой при Math.random=0 получено 10 given: 4 строки по 4 ячейки одинаковой ширины, 10 круглых и 6 квадратных. Первая попытка контрольного поиска русского заголовка не прошла из-за передачи текста в PowerShell/Node; проверка по строкам ячеек прошла. Файлы движка для этого не менялись, random восстановлен.
README содержит дерево scripts/preview.mjs и команду запуска. .mjs, запуск VS Code terminal, node --test и смысл --test объяснены пользователю.

## Обучение и понимание addRandomClue
Подробно разобрали Object.values: новый внешний массив ссылок на те же массивы групп, внутри — объекты подсказок. groups[0].pop меняет given при текущем порядке свойств, groups.pop меняет только внешний массив.
totalCount — число всех кандидатов, randomIndex — позиция в воображаемом общем массиве. При пропуске группы вычитается её длина, индекс становится локальным.
splice(start,deleteCount) меняет исходную группу, возвращает массив удалённых. Второй аргумент 1 удаляет один; 0/отрицательный ничего не удаляют. Отрицательный первый аргумент считает от конца. В памятке есть вставка через третий аргумент.
При будущих весах сначала выбирать доступный тип по весу, затем кандидата внутри, исключая пустые группы и лимиты. Это обсуждено, не реализовано.
Понимание новых механизмов развивается через конкретные примеры; опыт 1С значительный. Не считать объяснение полным освоением. Не просить заново разбирать preview сейчас.

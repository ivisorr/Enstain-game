## Фактический движок
Каталог 3 × 3: number-1/2/3, letter-a/b/c, roman-I/II/III. Регистр Roman ID сохранять.
answer перемешивает каждую строку через свободные индексы, исходный elements не меняется. Словари elementPositionById и answerPositionById внутренние, значения {rowIndex,colIndex}.
startGame: очищает visibleElements → generateRandomAnswer → fillAnswerPositionById → generateClueCandidates → selectClues.
После старта visibleElements пока [], endGame открывает весь ответ. Статусы, игроковые действия и матрица закрытых клеток ещё не реализованы.

clueCandidates: объект пяти массивов given/sameColumn/leftOf/near/between.
cluesSelected: один массив. selectClues очищает его и вложенными forEach копирует ВСЕХ кандидатов через {...clue}; из пула кандидаты не удаляются. Это учебная заглушка, не готовый выбор головоломки.
getClues копирует массив и каждый объект. getElements/getVisibleElements копируют строки. Все поля подсказок пока примитивы, поверхностного копирования достаточно. getClues не генерирует и не перемешивает заново.

given готов: {type:"given", element:ID, colIndex, id:"given:"+ID+":"+colIndex}.
sameColumn готов без random: для текущего элемента берём строки rowIndex+1 ... answer.length-1 в той же колонке. {type:"sameColumn", top:текущийID, bottom:нижнийID, id:"sameColumn:"+текущийID+":"+нижнийID}. Все пары созданы ровно раз, ID сразу нормализован по строкам каталога.
leftOf готов: для текущего элемента перебираем ВСЕ строки и колонки colIndex+1 ... row.length-1. {type:"leftOf", left:текущийID, right:найденныйID, id:"leftOf:"+текущийID+":"+найденныйID}. Элементы одной строки пока разрешены, настройки ещё не добавлены. Последняя колонка не создаёт leftOf, что правильно.

## ID, ориентация и проверки
ID добавляется при создании кандидата и сохраняется при переносе/копировании в выбранные. Выбрано имя id. Включаем тип и значимые поля.
- given: тип + ID элемента + колонка. Истинность и уникальность ID вместе обнаруживают неправильные повторные открытия.
- sameColumn: ID участников по порядку каталога (верхняя строка первой). ВАЖНОЕ изменение соглашения: поля top/bottom теперь места на изображении подсказки, не обязательный порядок строк. Случайная перестановка разрешена, ID не меняется.
- checkClue для sameColumn уже сравнивает равенство колонок и НЕРАВЕНСТВО строк, а не top.rowIndex < bottom.rowIndex.
- Тест ID строит локальный elementPositionById через fillPositionById(getElements()). Сравнивает строки top/bottom, тернарным оператором выбирает первый/второй ID и вычисляет ожидаемую строку. Готов к будущему random, но в реальной генерации обмена ещё нет.
- leftOf: участники не переставляются, ID сохраняет left/right.
- near: нормализовать пару по каталогу для ID; порядок side1/side2 случайный и не влияет на ID.
- between: центр отдельно, стороны нормализовать для ID; случайно менять только стороны, middle сохранять.
ID движка недостаточно просто считать уникальными: отдельный тест независимо сверяет ID с содержимым, затем другой тест проверяет Set.

## Девять сохранённых тестов
1. Размеры открытого поля относительно каталога.
2. Состав строк.
3. Независимость копии getElements.
4. Независимость копии getVisibleElements.
5. Сброс открытого поля: сначала подтвердить непустое после endGame, затем повторный startGame даёт [].
6. Истинность всех выданных подсказок: локальная checkClue(clue,positionsById) по открытому ответу. Реально проверяются given/sameColumn/leftOf; наличие веток near/between ещё не означает их практическое покрытие.
7. Независимость getClues: сохранить originalLength и originalClueType, изменить .type в копии, вызвать pop(), получить новую копию, сравнить исходный тип и длину. Универсально по типам. Набор между двумя геттерами не генерируется заново.
8. Уникальность id: локальный seenIds = new Set(); перед add проверяется !has.
9. Соответствие ID содержимому: ветки given, sameColumn с нормализацией, leftOf; неизвестный тип → assert.fail.
Помощник fillPositionById(sourceMatrix) создаёт новый словарь и возвращает его. В движке нет checkClue. Временный getElementPositionById пользователь добавлял ошибочно с .map по объекту, затем удалил: в тестах используем собственный помощник по getElements.
Сохранённые тесты НЕ проверяют полноту пула кандидатов. Решили не навязывать полноту будущему минимальному набору; возможные отдельные проверки генератора остаются задачей. Разовые проверки 40 игр не заменяют сохранённый тест.

## Алгоритм оставшихся типов — ранее согласован, пока без реализации
Обход elements, позиции из answerPositionById, соседи из answer.
near: соседние колонки с обеих сторон, но пару создаём только когда текущий ID раньше соседа в постоянном каталоге (rowIndex, затем colIndex), чтобы не было обратного дубля. Создать нормализованный ID, случайно выбрать порядок сторон.
between: каждый центр не в крайней колонке, все пары элементов из левой и правой соседних колонок. Каждая тройка с данным центром один раз. Все три ID различны; случайно меняются только стороны. Три элемента одной строки запрещены; два из одной строки допустимы. Флаги ограничений и значения по умолчанию ещё уточнять.
Финальное перемешивание не нужно при будущем случайном выборе из оставшихся кандидатов и сохранении порядка выбора без сортировки по ответу. Нынешняя заглушка selectClues не обеспечивает такую случайность.
Потом: выбор типа по весам, выбор кандидата, лимиты, решатель без угадывания, проверка единственности, сокращение. Эти этапы не реализованы.
Скрытие использованной подсказки — отдельная отложенная задача, вероятно слой 2; id может пригодиться.

## Опыт и договорённости
Длительный опыт 1С, непривычен синтаксис JS. Показать явную запись рядом с краткой при необходимости. Комментарии //+ и транслит переводить на русский.
В этой сессии разобраны: const запрещает переназначение, но не изменение содержимого; pop удаляет последний элемент; независимость копии; Set/has/add; assert.ok vs equal, assert.fail; тернарный аналог ?(,,) из 1С; переменные внутри объекта не создаются из имён соседних свойств; блоки циклов и точки с запятой.
Стиль: { в строке for/function; ; после объявлений/вызовов/присваиваний/return, не после блоков for/if/function. Учебные ошибки помогают объяснению, не считать одно объяснение освоением.
При видимой ошибке не запускать тесты до исправления (прямой запрос пользователя). Отдельную независимую проверку по правилам предлагать на завершённых логических блоках, делать по запросу — записано в AGENTS.

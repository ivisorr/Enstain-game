# Краткий контекст проекта

Обновлено: 2026-11-10. Подготовлена первоначальная организация работы и черновик архитектуры интерфейса; правила игры, стек и инструменты проверок ещё не выбраны.

## Цели

Создать веб-игру: сначала всё на frontend, со структурой, учитывающей будущий backend. Проект используется для обучения программированию, работе с AI, работе с двух компьютеров и CI/CD. Цели могут дополняться.

## Этапы проекта

Ориентир: подготовка переносимого контекста и среды → концепция игры → выбор технологий и платформы → начальная архитектура → прототип логическими блоками. Это план постепенной работы; не нужно полностью проектировать игру заранее.

## Окружение и синхронизация

- Планируются VS Code и Codex на бесплатных аккаунтах. Дома Codex ещё не установлен; ранее использовался бесплатный ChatGPT в браузере. Доступность и лимиты Codex для домашнего аккаунта нужно проверить.
- GitHub-репозиторий публичный, синхронизируется с локальным Git дома и на работе. Сейчас используется только ветка main.
- Работает один человек, поочерёдно с двух мест; параллельная работа не планируется.
- На текущем этапе выбрана связка VS Code + расширение Codex, как сейчас на работе. Установка дополнительного ПО возможна.
- ОС обоих компьютеров — Windows. Версии инструментов пока не уточнены.
- Код, описание, инструкции AI и история решений должны храниться в репозитории. Продолжение работы не должно зависеть от доступа к прежнему чату или тому же аккаунту.

## Опыт пользователя

- HTML/CSS: достаточно уверенно.
- JavaScript: понимает код AI, но методы и API пока знает недостаточно; готов разбираться.
- Git/GitHub: использует самостоятельно для синхронизации двух компьютеров.
- Терминал: небольшой опыт. Ветки и тесты: опыта нет.

## Предпочтения работы с AI

- Помогать формулировать задачи и разбивать их на небольшие шаги; писать код вместе.
- Предлагать подходящие методы, инструменты и практики, объясняя выбор.
- Проверять код пользователя и учить понятному, поддерживаемому коду.
- Объяснять, где и зачем применять тесты и CI/CD.
- Предлагать сохранять памятки важных этапов и операций, включая действия вне программирования.
- Глубина понимания важнее скорости получения результата.
- Сессии не имеют фиксированной длительности; желательно завершать их на логически законченном шаге.

## Фиксация результатов

Пользователь разрешил сохранять обсуждение и согласованные ответы внутри проекта. TASKS.md содержит задачи, а этот файл — краткое актуальное состояние и исходные ответы интервью, без полной стенограммы.

Согласованные решения записываются небольшими блоками сразу, без отдельного подтверждения каждой записи; в конце сессии AI показывает итог изменений. Карта документов предварительно принята и может корректироваться; см. WORKFLOW.md.

Код AI меняет только по запросу пользователя. Самостоятельный просмотр локального Git без изменений разрешён (git status, git diff, git log); команды обращения к GitHub не разрешены этим согласием. Commit и push пользователь выполняет сам. После завершения сессии и записи всех изменений AI автоматически предлагает краткий текст коммита.

## Следующий шаг

Формат обучения согласован: обсуждаем задачу → AI кратко объясняет шаг → пользователь пробует → вместе проверяем. Готовый код только по запросу. Непонятное пользователь спрашивает сам.

Созданы [LEARNING.md](LEARNING.md) с опытом и обучением, [TECHNOLOGY.md](TECHNOLOGY.md) с инструментами и [HISTORY.md](HISTORY.md) с промежуточным итогом. Они содержат профильные сведения; разделы выше пока оставлены как краткий обзор. Памятка начала и завершения сессии находится в [WORKFLOW.md](WORKFLOW.md), предварительная архитектура интерфейса — в [ARCHITECTURE.md](ARCHITECTURE.md).

Следующий содержательный шаг — обсудить концепцию и правила игры без кода. Черновик интерфейса сохранён в docs/ARCHITECTURE.md; его открытые вопросы уточнять после определения механики. Также предстоит проверить доступ к Codex дома, версии инструментов и подготовить переносимую памятку.

Сессия завершена по команде пользователя; итог и задачи обновлены. Локальный git status показал новые, ещё не отслеживаемые AGENTS.md, TASKS.md и docs/. Пользователю нужно включить их в коммит и выполнить push; выполнение не подтверждено. Дома сначала получить изменения GitHub, установить/проверить Codex и использовать стартовый текст из WORKFLOW.md. Если Codex недоступен, отдельно выбрать запасной способ работы. Код не менялся, проверки кода не запускались.

## Проверки и публикация

Сейчас приоритет — обучение программированию и инструментам разработки. Автоматические проверки нужны прежде всего для обучения и проверки собственной работы. Публикация игры возможна в будущем; автоматический деплой на текущем этапе не требуется. Конкретные проверки и инструменты пока не выбраны.

# Краткий контекст проекта

Обновлено: 2026-11-10. Текущая работа завершена для продолжения дома. Этап: правила и проектирование учебного прототипа движка; реализация ещё не начата в рамках этой сессии.

## Цель и правила работы

Frontend-веб-игра 6 × 6 с учётом будущего backend. Учебные цели: программирование, работа с AI, Git с двух компьютеров и CI/CD. Работаем только в Enstain-game; ограничения соседних папок — в AGENTS.md.

Один пользователь работает поочерёдно дома и на работе, Windows, VS Code + Codex, публичный GitHub, ветка main. Commit, push и получение изменений GitHub выполняет пользователь. AI разрешён просмотр локального Git без изменений. Домашняя установка/доступ к Codex и версии инструментов ещё не подтверждены в документации; сам факт работы дома не считать подтверждением настройки.

Обсуждаем небольшой шаг → AI кратко объясняет → пользователь пробует → вместе разбираем. Код приложения только по запросу; показанные по запросу примеры не означают разрешения создавать файлы реализации. Согласованные решения сохраняем сразу. Элементы в объяснениях обозначаем [A], [1], [II], индексы — без скобок.

## Согласованные результаты

- Постоянные наборы и позиции строк; для скрытого ответа перемешиваем копии наборов.
- Три горизонтальных отношения и вертикальное «одна колонка». Для каждого горизонтального типа отдельно настраивается повторение строк; вертикальные всегда из разных строк.
- Единственный ответ, достижимый начальными логическими приёмами: исключения по подсказкам, единственный вариант клетки и единственное место элемента. При удалении подсказок сохранять единственность и прохождение логического решателя.
- Полное MP истинных уникальных кандидатов, пять групп по типам. Выбор группы по весу, кандидата внутри группы — случайно без повторов. Выбранное переносим из MP в отдельный набор; флаг selected не нужен.
- Отдельный лимит открытых клеток; веса и лимит ещё не выбраны. Сначала подбор достаточной информации, затем сокращение и проверка. Веса не гарантируют итоговые пропорции.
- Пользователь правильно решил учебный пример 3 × 3. Основная игра остаётся 6 × 6.

## Место остановки

Подробное продолжение — в [HANDOFF.md](HANDOFF.md), статус активный. Пользователь предпочитает понятные имена элементов и типов, но хочет удобные циклы и индексы. Показаны примеры массивов объектов, обращения по индексу, find/getElement и словарей. Окончательное представление данных пока не выбрано.

Дома сначала прочитать активный HANDOFF.md и изменения предыдущего сеанса. Продолжить объяснение примеров или согласовать структуру одной подсказки с пользователем. Не начинать код и не повторять уже закрытое обсуждение MP.

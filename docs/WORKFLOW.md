# Организация работы

Статус: рабочая версия по итогам интервью. Памятку начала и завершения сессии уточняем по практике.

Карта предварительно принята и может изменяться. Все перечисленные документы созданы. Памятки по отдельным операциям добавляются по необходимости. Подробности хранятся в профильном документе, CONTEXT.md содержит краткое состояние и ссылки.

## Согласованные правила

- Согласованные решения и ответы AI фиксирует в документации сразу небольшими блоками, без отдельного подтверждения каждой записи.
- В конце сессии AI показывает итог изменений в файлах.
- AI изменяет код только по запросу пользователя; обсуждение и запись задачи сами по себе не разрешают реализацию.
- AI может самостоятельно смотреть локальное состояние Git командами без изменений (например git status, git diff, git log). Изменение состояния Git и команды обращения к GitHub, включая fetch, pull и push, этим разрешением не охватываются.
- Commit и push пользователь выполняет самостоятельно. При завершении AI автоматически предлагает краткий текст коммита на русском языке.
- Приоритет — понимание и обучение; работа ведётся небольшими шагами.
- Текущая связка инструментов — VS Code + расширение Codex. Дополнительное ПО можно устанавливать при необходимости.
- Репозиторий публичный; сейчас пользователь работает только в main. Будущий порядок применения веток ещё не определён.
- Автоматизацию начинаем с проверок для обучения и контроля своей работы. Публикация возможна в будущем; автоматический деплой пока не требуется. Проверки и инструменты ещё не выбраны.

## Ещё предстоит определить

- Подход к веткам, проверкам и инструментам тестирования.
- Окружение обоих компьютеров и необходимые памятки.

План проекта: подготовка переносимого контекста и среды → концепция игры → выбор технологий и платформы → начальная архитектура → прототип логическими блоками. Это ориентир, а не требование заранее подробно проектировать всю игру; этапы уточняются по мере появления решений.

## Начало сессии

1. Пользователь открывает Enstain-game в VS Code и проверяет состояние Git. При незавершённых изменениях сначала разобраться с ними, не удалять их ради синхронизации.
2. Пользователь получает изменения из GitHub до новой работы. При конфликте или неожиданном состоянии остановиться и обратиться за разбором.
3. Запустить Codex в папке проекта со стартовым текстом ниже.
4. AI читает AGENTS.md, CONTEXT.md, TASKS.md, активный HANDOFF.md и эту памятку, затем просматривает локальное состояние Git (status, diff и недавнюю историю коммитов). Остальное — по необходимости. Кратко сообщает обнаруженные изменения, состояние и этап проекта, открытые вопросы и предлагает следующий шаг, чтобы пользователь мог проверить восстановленный контекст.
5. Пользователь выбирает шаг. Задача в списке сама по себе не разрешает писать код.

Обязательная часть шага 4: прочитать итог предыдущего сеанса в HISTORY.md, изменения соответствующих локальных коммитов и новые/изменённые заметки, включая архитектуру и связанные эскизы. Список файлов и сообщения коммитов не заменяют чтение содержания. Предыдущий сеанс может включать несколько коммитов; границу определять по истории и контексту. При большом объёме сначала согласовать анализ с пользователем согласно AGENTS.md.

Стартовый текст для нового чата:

> Продолжаем Enstain-game. Прочитай AGENTS.md, docs/CONTEXT.md, TASKS.md, docs/WORKFLOW.md и активный docs/HANDOFF.md; проверь локальное состояние Git командами status, diff и log и прочитай изменения предыдущего сеанса. Кратко восстанови состояние и предложи продолжение с места остановки в HANDOFF.md. Остальные файлы читай только по необходимости. Код пока не пиши. Если доступа к локальным файлам нет, сообщи об этом, не предполагая их содержание.

## В процессе

Обсуждаем задачу → AI кратко объясняет шаг → пользователь пробует → вместе проверяем и разбираем. Готовый код — по запросу. Согласованные решения и задачи записываются сразу небольшими блоками. AI предлагает памятки для повторяемых операций. Когда задача даёт подходящую возможность, AI подсказывает небольшой следующий шаг по тестированию или CI/CD и объясняет его учебную пользу; внедрение инструмента согласуется с пользователем. К проверкам и тестам переходим после выбора стека и появления подходящей практической задачи. CI вводим, когда есть повторяемые локальные проверки; CD обсуждаем, когда появится цель публикации.

## Завершение сессии

Команда: «Завершаем сессию, зафиксируй в файлах».

1. Не начинать новых задач. Обновить задачи, согласованные решения, опыт и технологии в соответствующих документах.
2. Обновить CONTEXT.md: состояние, незавершённое, препятствия и ближайший шаг. Обновить HANDOFF.md по правилам буфера ниже.
3. Добавить краткий итог в HISTORY.md. Не записывать запланированное как выполненное и не заявлять о непроведённых проверках.
4. Проверить согласованность документов и ссылки. Показать изменённые файлы, открытые вопросы и шаг для продолжения.
5. AI предлагает краткий текст коммита. Пользователь проверяет изменения и текст, затем сам делает commit и push. Отправку не считать состоявшейся без подтверждения или проверки.
6. На другом компьютере повторить порядок начала сессии. Без отправки изменений новая копия не получит последние результаты.

## Жизненный цикл HANDOFF.md

- CONTEXT.md — короткий актуальный обзор; HISTORY.md — постоянные итоги; HANDOFF.md — подробности последнего незавершённого обсуждения, включая примеры кода и причины сомнений.
- По просьбе пользователя или при завершении сессии обновлять буфер: тема, дата, статус, согласованное, предложения, примеры, открытый вопрос и следующий шаг. Не требуется полная стенограмма чата.
- Если тема не разобрана, сохранить нужные подробности и объединить их с новыми уточнениями. Само чтение файла, завершение сессии или commit не означают завершения темы.
- При завершении темы перенести устойчивые решения в профильные документы, задачи — в TASKS.md, итог — в HISTORY.md. После этого заменить старое содержимое новым незавершённым контекстом, если он появился.
- Если нового незавершённого контекста нет, оставить короткий статус «Нет активного обсуждения», дату и ссылки на результаты. Сам файл не удалять.
- Использовать относительные ссылки, чтобы буфер работал после переноса проекта. Не хранить секреты и персональные данные в публичном репозитории.

## Памятка для будущих проектов

Нужна прежде всего пользователю: не пропускать организационные шаги и передавать AI контекст независимо от компьютера и чата. После интервью подготовить переносимый вариант с заменяемыми названием проекта, ограничениями, опытом и инструментами.

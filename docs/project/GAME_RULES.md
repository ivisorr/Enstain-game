# Правила игры

Статус: уточняются с пользователем. Здесь подтверждённая механика, без выбора алгоритмов и стека.

## Поле и решение

- Поле состоит из 6 строк и 6 столбцов.
- Каждой строке постоянно соответствует свой набор из 6 уникальных элементов. Например: первая — 1–6, вторая — A–F, третья — I–VI, четвёртая — грани кости. Окончательные наборы и изображения ещё не выбраны.
- Набор элементов и позиция каждой строки фиксированы между играми. Если цифрам назначена строка 1, они всегда остаются в строке 1, а не переходят в другую. Меняется только расположение элементов внутри строки. Здесь номера строк 1–6 — пользовательские обозначения; способ индексации в коде ещё не выбран.
- В решении каждая строка содержит перестановку своих шести элементов: каждый встречается ровно один раз. Порядок набора для отображения вариантов не задаёт порядок элементов в решении.
- В начале игры алгоритм должен сформировать случайное решение и подобрать минимально необходимые подсказки, чтобы головоломку можно было решить.
- Постоянные наборы строк сохраняются неизменными. Для скрытого ответа независимо перемешиваются их копии, без повторов и пропусков элементов. Этот способ формирования ответа согласован; порядок подбора подсказок и открытых клеток ещё обсуждается.
- Изначально элементы скрыты; некоторые могут быть открыты, если это необходимо для решения вместе с подсказками.
- Головоломка должна иметь ровно одно решение и допускать логическое решение без угадывания. Набор допустимых логических приёмов ещё предстоит определить: единственность сама по себе не гарантирует требуемого способа решения.
- Игрок может угадывать: игра не определяет способ его рассуждений, проверяется только правильность ответа. Когда именно выполнять проверку, ещё не согласовано.

## Генерация и сложность

- Для первого прототипа согласовано полное множество истинных допустимых кандидатов clueCandidates, разделённое на пять групп: два соседа, «левее», трое соседей, вертикальные пары и открытия клеток.
- При добавлении сначала выбирать доступную группу по её весу, затем случайного кандидата внутри группы без повторов. Пустые группы и открытия клеток при достижении их лимита исключаются из выбора. Число кандидатов группы не определяет вероятность выбора её типа.
- clueCandidates хранит только ещё не выбранных кандидатов. Выбранного кандидата удалять из его группы clueCandidates и переносить в отдельный выбранный набор. Отдельный признак selected и повторная проверка наличия в выбранном наборе не нужны при условии уникальности исходных кандидатов.
- При сокращении готового набора временно исключать подсказку: возвращать её в выбранный набор, если требования перестают выполняться, иначе удалять окончательно. В clueCandidates её не возвращать, поскольку этап добавления завершён. Для новой игры формировать новый набор clueCandidates.
- Использовать отдельный лимит открытых клеток. Конкретные веса и лимит пока не выбраны; значения 3/3/3/3/1 обсуждались только как пример.
- Веса задают предпочтения при добавлении, но не гарантируют пропорции итоговой задачи, особенно после удаления лишних подсказок. Жёсткие квоты всех типов пока не вводить; оценку разнообразия и возможный критерий приёмки уточнять на примерах.
- Рабочий критерий минимальности: нельзя удалить ни одну подсказку, сохранив одновременно единственность и решение логическим решателем выбранного уровня, при фиксированных исходных открытых элементах. Математически избыточная подсказка может остаться ради понятного решения. Искать абсолютный минимум количества подсказок среди всех наборов не требуется.
- Начальные приёмы решателя: исключение позиций, несовместимых с подсказкой и текущими вариантами; единственный вариант клетки; единственное место элемента в строке. Повторять до решения или остановки без новых выводов. Для отношений с несколькими элементами учитывать совместимость всей подсказки. Угадывание и перебор предположений не входят в эти учебные приёмы.
- Пользователь предварительно принял эти приёмы; следующий шаг — разобраться на ручном примере 3 × 3 до написания кода. Основная игра остаётся 6 × 6.
- Для лёгкого уровня допускается обсудить небольшую избыточность подсказок или другие способы снижения сложности. Способ пока не выбран; вернуться к вопросу при работе над генерацией и уровнями сложности.
- Правила выбора исходных открытых элементов пока не определены.
- Для каждого из трёх горизонтальных типов генератор должен иметь отдельную настройку: разрешено ли участие элементов одной строки. Для тройной подсказки это выбор между «все строки разные» и «повторение строк разрешено», включая два или три элемента одной строки. Значения по умолчанию пока не выбраны.
- Это параметры допустимых подсказок, а не гарантированные уровни сложности. Их влияние на сложность оценить на примерах при разработке генератора.

## Подсказки

Под колонкой элемента понимается его столбец в решении. Внешний вид обозначений пока взят из эскиза.

На текущем этапе список типов принят: три горизонтальных и один вертикальный. Вертикальные подсказки имеют другую высоту и выводятся отдельным блоком, как указано в ARCHITECTURE.md.

### Соседние колонки — красная двусторонняя стрелка

Два различных элемента находятся в соседних колонках. Участие элементов одной строки определяется настройкой этого типа. Кто левее, не указано. Например, [1] ↔ [V]: 1 может находиться в колонке 3, V — в колонке 2, или наоборот по направлению.

### Левее — красные точки

Первый элемент находится строго левее второго; соседство не обязательно. Элементы различны; участие элементов одной строки определяется настройкой этого типа. Например, [5] … [D] допускает колонки 2 и 6 или 1 и 4 соответственно.

### Три соседних элемента — синяя стрелка

Все три элемента различны; повторение строк определяется настройкой этого типа. Центральный элемент подсказки расположен между двумя другими в трёх последовательных колонках. Крайние элементы можно поменять местами. Центральный не может находиться в колонке 1 или 6.

Пример: [4] < [I] > [F] допускает I в колонке 5, 4 в колонке 6 и F в колонке 4; также допускается обратное расположение крайних элементов.

### Одна колонка — вертикальная подсказка

Два элемента из разных строк расположены в одной колонке.

## Возможное расширение: порядок строк

Для максимальной сложности можно рассмотреть изменение порядка строк, но это не принятое требование. Сейчас позиции строк фиксированы. При проектировании движка оценить стоимость такого расширения и обсудить её с пользователем, прежде чем решать о реализации. Не добавлять режим или сложную инфраструктуру заранее.

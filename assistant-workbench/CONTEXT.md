# Краткий контекст Assistant Workbench

Обновлено: 2026-11-21.

## Состояние

Создана документационная мастерская будущего переносимого помощника. Все пять навыков признаны необходимыми модулями; включение задаётся в каждом проектном профиле. Правила навыков могут быть экспериментальными, но экспериментальные правила применяются в выбравшем их проекте. Технический агент, плагин и установка не создавались.

Учебная память разделена: переносимый подход помощника и известные предпочтения обучения записаны в `skills/learning.md`; цели и наблюдаемый прогресс по Enstain-game остаются в `docs/workflow/LEARNING.md`.

Базовая модель: общее ядро + рабочие навыки + профиль и память каждого проекта + отдельные инструменты/интеграции. Корневой `AGENTS.md` Enstain-game направляет работу к подтверждённым правилам этой папки.

## Подтверждено

- Для нетривиальных изменений: проанализировать задачу, уточнить существенные пробелы, кратко пересказать понимание и границы, получить подтверждение, затем перейти к следующему этапу; код и тесты по-прежнему требуют отдельного показа и запроса перед изменением файлов.
- Уточнять поведение и важные границы до показа кода.
- Сначала показывать реализацию в чате; файлы менять по отдельной просьбе после разбора и принятия.
- Сценарии тестов обсуждать заранее; обучение совмещать с развитием проекта без обязательных упражнений.
- Вести отдельные контекст, передачу, задачи и историю помощника; эти документы описывают разработку и не являются активными инструкциями.
- В нашей работе «агент» без уточнения означает черновик Assistant Workbench.
- Неизвестные по нужности идеи оставлять вне `skills/`; экспериментальные правила выбранных навыков применять и уточнять по практике.

## Ближайший шаг

По мере новых задач отмечать практические результаты и уточнять экспериментальные правила. Вопросы о способе установки на домашнем и рабочем компьютерах оставить на этап, когда модули стабилизируются.

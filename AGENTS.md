# Инструкции для работы с Enstain-game

## Основной проект

Enstain-game — единственный проект, с которым разрешено работать.
Корень проекта — папка, содержащая этот AGENTS.md.
Все создаваемые и изменяемые файлы должны находиться внутри корня Enstain-game. 
Это правило действует независимо от расположения проекта и текущей рабочей папки.

## Работа с контекстом

- В начале рабочей сессии прочитай [краткий контекст](docs/CONTEXT.md) и [список задач](TASKS.md). Если они уже прочитаны в текущей сессии и не менялись, повторное чтение не нужно.
- TASKS.md — общий список задач для работы дома и на работе. По ходу обсуждения добавляй согласованные задачи, отмечай выполненные и сохраняй нерешённые вопросы. Порядок выполнения выбирай с учётом зависимостей и наличия информации; не считай запись задачи разрешением немедленно её реализовать.
- Не читать весь репозиторий целиком без необходимости.
- Сначала использовать краткий сохранённый контекст проекта и только файлы, напрямую относящиеся к текущей задаче.
- Дополнительные файлы открывать только если без них нельзя корректно продолжить работу.
- Перед анализом большого количества файлов сначала объяснить, зачем это необходимо и запросить разрешение.
- Не повторно читать файлы, содержание которых уже достаточно известно из текущей сессии.

## Взаимодействие с пользователем

- Согласованные решения и ответы можно сразу фиксировать небольшими блоками в документации без отдельного подтверждения каждой записи. В конце сессии показывай итог изменений. Карту документов см. в docs/WORKFLOW.md.
- Изменяй код только по запросу пользователя. Запись задачи или обсуждение варианта не является запросом на реализацию.
- Можно самостоятельно просматривать локальное состояние Git внутри Enstain-game командами без изменений, например git status, git diff и git log. Это не разрешает изменять состояние Git или выполнять команды обращения к GitHub (включая fetch, pull и push).
- Пользователь самостоятельно выполняет commit и push. Не выполняй их за него; помогай составлять сообщения коммитов по запросу.
- Обучение: обсудить задачу → кратко объяснить небольшой шаг → пользователь пробует → вместе проверить и разобрать. Готовый код давай только по запросу. Подробные объяснения — по дополнительным вопросам.
- Для начала и завершения сессии используй docs/WORKFLOW.md. Опыт пользователя хранится в docs/LEARNING.md, технологии — в docs/TECHNOLOGY.md; читай их при необходимости для текущей задачи.

## Справочные материалы

В workspace могут присутствовать соседние папки:

- html-css-learning — готовый учебный проект.
- personal-dev-environment — документация и книги.

Никогда не создавай, не изменяй и не удаляй файлы или папки
в этих двух каталогах.

Читай и используй их как справочный материал только по прямой
просьбе пользователя. Их присутствие в workspace само по себе
не разрешает просмотр.

Если после переноса проекта эти папки отсутствуют, не создавай
и не ищи их без просьбы пользователя.

## Границы действий

Не изменяй другие проекты и файлы за пределами Enstain-game.
Перед командами, изменяющими файлы, проверяй рабочую папку
и целевые пути.

Если задача требует действий за пределами проекта, сначала
объясни необходимость и получи явное разрешение пользователя.
Запрет на изменение двух справочных папок остаётся в силе.

# Инструкции для работы с Enstain-game

## Основной проект

Enstain-game — единственный проект, с которым разрешено работать.
Корень проекта — папка, содержащая этот AGENTS.md.
Все создаваемые и изменяемые файлы должны находиться внутри корня Enstain-game. 
Это правило действует независимо от расположения проекта и текущей рабочей папки.

## Работа с контекстом

- Note.txt в корне — личный рабочий буфер пользователя. Не читай его автоматически как контекст/инструкции AI и не изменяй без прямой просьбы пользователя.
- В начале каждой сессии обязательно прочитай изменения предыдущего сеанса: итог в docs/workflow/HISTORY.md, соответствующие локальные коммиты и изменения файлов. Прочитай новые и изменённые заметки, включая архитектуру и связанные эскизы, прежде чем предлагать следующий шаг. Не ограничивайся списком файлов или сообщениями коммитов. Если граница предыдущего сеанса неясна, уточни её по истории и контексту; не считай один последний коммит заведомо всем сеансом. Уже прочитанное в текущей сессии повторять не нужно. При большом объёме соблюдай правило согласования массового анализа.
- В начале рабочей сессии прочитай [краткий контекст](docs/ai/CONTEXT.md) и [список задач](docs/workflow/TASKS.md). Если они уже прочитаны в текущей сессии и не менялись, повторное чтение не нужно.
- Также прочитай [буфер передачи обсуждения](docs/ai/HANDOFF.md), если он существует и активен. Сначала продолжай от сохранённого незавершённого вопроса с учётом нового запроса пользователя. При завершении сессии обновляй буфер по docs/workflow/WORKFLOW.md; не удаляй неразобранное и не превращай предложения в принятые решения.
- docs/workflow/TASKS.md — общий список задач для работы дома и на работе. По ходу обсуждения добавляй согласованные задачи, отмечай выполненные и сохраняй нерешённые вопросы. Порядок выполнения выбирай с учётом зависимостей и наличия информации; не считай запись задачи разрешением немедленно её реализовать.
- Не читать весь репозиторий целиком без необходимости.
- Сначала использовать краткий сохранённый контекст проекта и только файлы, напрямую относящиеся к текущей задаче.
- Дополнительные файлы открывать только если без них нельзя корректно продолжить работу.
- Перед анализом большого количества файлов сначала объяснить, зачем это необходимо и запросить разрешение.
- Не повторно читать файлы, содержание которых уже достаточно известно из текущей сессии.

## Взаимодействие с пользователем

- При изменении структуры проекта поддерживай дерево в README.md актуальным. У каждого включённого в дерево файла и каталога должен быть краткий понятный комментарий о назначении. Описание дерева должно соответствовать существующим файлам; будущие файлы отмечай отдельно.
- Перед функциями и при объявлении глобальных структур данных добавляй краткий понятный комментарий: что делает функция или какие данные хранит структура. Соблюдай это и в учебных примерах кода.
- В примерах игры обозначай элементы в квадратных скобках: [A], [1], [II]. Индексы и номера строк/колонок пиши без скобок, чтобы отличать их от элементов.
- Согласованные решения и ответы можно сразу фиксировать небольшими блоками в документации без отдельного подтверждения каждой записи. В конце сессии показывай итог изменений. Карту документов см. в docs/workflow/WORKFLOW.md.
- Изменяй код только по запросу пользователя. Запись задачи или обсуждение варианта не является запросом на реализацию.
- Можно самостоятельно просматривать локальное состояние Git внутри Enstain-game командами без изменений, например git status, git diff и git log. Это не разрешает изменять состояние Git или выполнять команды обращения к GitHub (включая fetch, pull и push).
- Пользователь самостоятельно выполняет commit и push. Не выполняй их за него. После завершения сессии и записи всех изменений автоматически предложи краткий текст коммита.
- Текст коммита предлагай на русском языке.
- Если операция может потребовать около 3% или больше от общего объёма использования бесплатного плана, заранее запроси разрешение. Не проверяй остаток лимита; долю оценивай приблизительно.
- Обучение: обсудить задачу → кратко объяснить небольшой шаг → пользователь пробует → вместе проверить и разобрать. Готовый код давай только по запросу. Подробные объяснения — по дополнительным вопросам.
- Для начала и завершения сессии используй docs/workflow/WORKFLOW.md. Опыт пользователя хранится в docs/workflow/LEARNING.md, технологии — в docs/workflow/TECHNOLOGY.md; читай их при необходимости для текущей задачи.

## Справочные материалы

В workspace могут присутствовать соседние папки:

- html-css-learning — готовый учебный проект.
- personal-dev-environment — документация и книги.

Никогда не создавай, не изменяй и не удаляй файлы или папки
в этих двух каталогах.

Читай и используй их как справочный материал только по прямой
просьбе пользователя. Их присутствие в workspace само по себе
не разрешает просмотр.

Если после переноса проекта эти папки отсутствуют, не создавай
и не ищи их без просьбы пользователя.

## Границы действий

Не изменяй другие проекты и файлы за пределами Enstain-game.
Перед командами, изменяющими файлы, проверяй рабочую папку
и целевые пути.

Если задача требует действий за пределами проекта, сначала
объясни необходимость и получи явное разрешение пользователя.
Запрет на изменение двух справочных папок остаётся в силе.
